# Scheduled Jobs vs Cron Jobs: What's the Difference?

## Scheduled Jobs (General Concept)

A **scheduled job** is a general term for any task that runs automatically at predetermined times or intervals. This is a broad concept that applies across all operating systems and platforms.

**Examples of scheduled job systems:**
- Windows Task Scheduler
- macOS launchd
- Linux cron/systemd timers
- Cloud schedulers (AWS EventBridge, Google Cloud Scheduler)
- Application-level schedulers (Celery Beat, APScheduler, Quartz)

**Key characteristics:**
- Can be triggered by time, events, or conditions
- Platform-agnostic concept
- May run once or repeatedly
- Can be managed through various tools and interfaces

## Cron Jobs (Specific Implementation)

A **cron job** is a specific implementation of scheduled jobs native to Unix/Linux systems. It uses the `cron` daemon and a specific syntax called "cron expression" to define when tasks run.

**Cron expression format:**
```
* * * * * command
│ │ │ │ │
│ │ │ │ └── Day of week (0-7, Sunday = 0 or 7)
│ │ │ └──── Month (1-12)
│ │ └────── Day of month (1-31)
│ └──────── Hour (0-23)
└────────── Minute (0-59)
```

**Example cron jobs:**
- `0 9 * * 1-5` = Run at 9 AM, Monday through Friday
- `*/15 * * * *` = Run every 15 minutes
- `0 0 1 * *` = Run at midnight on the 1st of each month

**Key characteristics:**
- Unix/Linux specific (though syntax adopted elsewhere)
- Uses crontab files for configuration
- Time-based triggering only
- Lightweight and reliable

## Summary

| Aspect | Scheduled Job | Cron Job |
|--------|---------------|----------|
| Scope | General concept | Specific implementation |
| Platform | Any | Unix/Linux |
| Trigger types | Time, events, conditions | Time only |
| Configuration | Varies by tool | Crontab + cron syntax |

**In short:** All cron jobs are scheduled jobs, but not all scheduled jobs are cron jobs. Cron is just one way (the Unix way) to schedule tasks.
